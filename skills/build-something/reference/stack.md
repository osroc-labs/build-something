# The stack

One shape for every app, so every build goes the same way:

- **A Cloudflare Worker** serves the page and the `/api` routes (Hono for routing).
- **The page** is plain HTML/CSS/JS in `public/`, served as static assets. No build step: the approved prototype drops straight in. For a richer UI, load Preact + htm or Alpine from a CDN `<script type="module">` inside the page; still no build step.
- **The data** lives in a **Durable Object** with built-in SQLite, queried through **Drizzle**. No separate database to create, no connection strings, free on the Workers free plan.

## Scaffold

Run in `~/apps/<app-name>/` (prefix with the `PATH_LINE` export if setup printed one):

```bash
npm init -y >/dev/null
npm pkg set type=module scripts.dev="wrangler dev" scripts.deploy="wrangler deploy" scripts.db="drizzle-kit generate" scripts.types="wrangler types"
npm i hono drizzle-orm
npm i -D wrangler drizzle-kit typescript
mkdir -p src/db public
```

Then write the files below, replacing `<app-name>` and today's date, run `npm run db && npm run types`, and `git init` with a `.gitignore` of `node_modules/`, `.wrangler/`, `.dev.vars`.

If git has no identity yet, set one on the repo only: `git config user.name "Me" && git config user.email "me@localhost"`.

### `wrangler.jsonc`

```jsonc
{
  "$schema": "node_modules/wrangler/config-schema.json",
  "name": "<app-name>",
  "main": "src/index.ts",
  "compatibility_date": "<YYYY-MM-DD today>",
  "compatibility_flags": ["nodejs_compat"],
  "assets": {
    "directory": "./public",
    "not_found_handling": "single-page-application",
    "run_worker_first": ["/api/*"]
  },
  "durable_objects": {
    "bindings": [{ "name": "DB", "class_name": "AppDatabase" }]
  },
  "migrations": [{ "tag": "v1", "new_sqlite_classes": ["AppDatabase"] }],
  "rules": [{ "type": "Text", "globs": ["**/*.sql"], "fallthrough": true }],
  "observability": { "enabled": true }
}
```

The `migrations` block above is Cloudflare's list of Durable Object *classes*, not database tables. Only touch it when adding a new Durable Object class (append `{ "tag": "v2", "new_sqlite_classes": ["NewClass"] }`); never edit or remove an existing entry.

### `src/db/schema.ts`

Model the v1 actions from `APP.md`. Example:

```ts
import { sqliteTable, integer, text } from "drizzle-orm/sqlite-core";

export const items = sqliteTable("items", {
  id: integer("id").primaryKey({ autoIncrement: true }),
  text: text("text").notNull(),
  done: integer("done", { mode: "boolean" }).notNull().default(false),
  createdAt: integer("created_at", { mode: "timestamp_ms" })
    .notNull()
    .$defaultFn(() => new Date()),
});
```

### `src/index.ts`

```ts
import { DurableObject } from "cloudflare:workers";
import { Hono } from "hono";
import { drizzle, type DrizzleSqliteDODatabase } from "drizzle-orm/durable-sqlite";
import { migrate } from "drizzle-orm/durable-sqlite/migrator";
import { desc, eq } from "drizzle-orm";
// @ts-ignore: generated by drizzle-kit
import migrations from "../drizzle/migrations";
import * as schema from "./db/schema";

// All data lives here. Each public method is callable from the Worker.
export class AppDatabase extends DurableObject<Env> {
  db: DrizzleSqliteDODatabase<typeof schema>;

  constructor(ctx: DurableObjectState, env: Env) {
    super(ctx, env);
    this.db = drizzle(ctx.storage, { schema });
    ctx.blockConcurrencyWhile(async () => {
      await migrate(this.db, migrations);
    });
  }

  listItems() {
    return this.db.select().from(schema.items).orderBy(desc(schema.items.id)).all();
  }

  addItem(text: string) {
    return this.db.insert(schema.items).values({ text }).returning().get();
  }

  setDone(id: number, done: boolean) {
    return this.db.update(schema.items).set({ done }).where(eq(schema.items.id, id)).returning().get();
  }
}

const app = new Hono<{ Bindings: Env }>();

// One shared database for the whole app. See "Separate spaces" for per-list/per-room data.
const db = (env: Env) => env.DB.get(env.DB.idFromName("main"));

app.get("/api/items", async (c) => c.json(await db(c.env).listItems()));

app.post("/api/items", async (c) => {
  const { text } = await c.req.json<{ text: string }>();
  if (!text?.trim()) return c.json({ error: "text is required" }, 400);
  return c.json(await db(c.env).addItem(text.trim()), 201);
});

app.patch("/api/items/:id", async (c) => {
  const { done } = await c.req.json<{ done: boolean }>();
  return c.json(await db(c.env).setDone(Number(c.req.param("id")), done));
});

export default app;
```

## Changing the data

Edit `src/db/schema.ts`, run `npm run db` (writes a new migration into `drizzle/`), restart `wrangler dev`. The Durable Object applies new migrations by itself on its next start, locally and after deploy. Add columns as nullable or with a default so existing rows survive. Dropping a table or column deletes real people's data: ask first.

## Run and check locally

```bash
npx wrangler dev --port 8787        # run in the background
curl -s localhost:8787/api/items
curl -s -X POST localhost:8787/api/items -H 'content-type: application/json' -d '{"text":"hello"}'
```

Local data lives in `.wrangler/` and is separate from the live site's.

## Patterns for common ideas

Reach for these only when the idea needs them.

### Separate spaces (lists, rooms, games, groups)

Give each space its own Durable Object: same class, different name. Create a space with a random id and put it in the URL (`/s/<id>`); anyone with the link can use it. That is the default answer for "private" data: no accounts needed.

```ts
const space = (env: Env, id: string) => env.DB.get(env.DB.idFromName(`space:${id}`));
app.get("/api/s/:id/items", async (c) => c.json(await space(c.env, c.req.param("id")).listItems()));
```

### Live updates (chat, multiplayer, shared boards)

Use WebSockets on the Durable Object with the hibernation API, so idle connections cost nothing:

```ts
// inside AppDatabase
async fetch(request: Request) {
  const pair = new WebSocketPair();
  this.ctx.acceptWebSocket(pair[1]);
  return new Response(null, { status: 101, webSocket: pair[0] });
}
webSocketMessage(ws: WebSocket, message: string | ArrayBuffer) {
  for (const peer of this.ctx.getWebSockets()) peer.send(message); // or save first, then broadcast
}

// in the Worker
app.get("/api/s/:id/live", (c) => space(c.env, c.req.param("id")).fetch(c.req.raw));
```

The page connects with `new WebSocket(location.origin.replace("http", "ws") + "/api/s/<id>/live")` and reconnects on close.

### AI features (summarise, chat, generate)

Use Workers AI: no API key, free daily allowance. Add `"ai": { "binding": "AI" }` to `wrangler.jsonc`, run `npm run types`, then `await c.env.AI.run("<model>", { messages })`. Look up a current model in Cloudflare's Workers AI docs (via the Cloudflare MCP when it's connected). AI calls run against Cloudflare even during `wrangler dev`, so the first one needs the login from Step 5.

### Accounts and sign-in

Avoid for v1; links to separate spaces cover most needs. If the idea truly needs people to sign in, ask the person before adding it, and pick the simplest thing that works.

### Files and photos

Small images (under ~1 MB) can be stored as base64 text in SQLite. Anything bigger needs R2, which requires adding a payment method to their Cloudflare account: ask first.

### Secrets (third-party API keys)

Never put keys in code. Locally: `.dev.vars` (`KEY=value`). Live: `npx wrangler secret put KEY`, which prompts for the value; have the person paste it in themselves.
